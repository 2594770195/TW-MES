# Requirements: 库存盘点更新

## 状态
- **状态**：草稿 Draft
- **创建日期**：2026-06-18
- **来源需求**：`MES/库存盘点更新`
- **目标对象**：通过 Excel 或数据库查询结果，对 `WW_RMInventory` 库存表按仓库维度进行盘点更新

---

## 1. 背景与目标

### 1.1 背景
仓库盘点后，业务人员会得到一份 Excel 或数据库查询结果。该结果记录了某个工厂、某个仓库下，每个物料 SAP 批次的实际库存数量。盘点来源不提供 MES 内部批次 `LotSN`，系统需要按 SAP 批次匹配并更新 MES 库存表 `WW_RMInventory`，保证 MES 中的库存数量和实际盘点结果一致。

### 1.2 目标
- 支持按工厂、仓库、物料、SAP 批次导入盘点数据。
- 以仓库 `WorkcenterId` 为单位分别更新库存，避免一个仓库失败影响其他仓库。
- 对盘点结果中存在的 SAP 批次，按 `FactoryId + WorkcenterId + ProductId + ProductionLotNO` 更新或新增库存记录，并将需要保留的库存设置为 `IsStorage=1`。
- 对库存表中存在但盘点结果中不存在的 SAP 批次，将 `IsStorage` 设置为 `0`。
- 返回每个仓库的处理结果，方便业务人员确认更新是否成功。

### 1.3 非目标（本期不做）
- 不直接实现 Excel 前端上传页面。
- 不处理跨系统 SAP 回写。
- 不自动创建不存在的工厂、仓库、物料、单位主数据。
- 不删除 `WW_RMInventory` 物理记录，只通过 `IsStorage` 标记是否在库。
- 不处理非本次盘点仓库范围之外的库存数据。

---

## 2. 输入数据要求

### 2.1 Excel 或查询结果字段
盘点数据必须包含以下字段：

| 字段 | 是否必填 | 示例 | 说明 |
|---|---|---|---|
| 工厂 | 是 | 一厂 | 用于定位工厂主数据 |
| 仓库 | 是 | 原材料仓 | 用于定位仓库 `WorkcenterId` |
| 物料号 | 是 | RM001 | 用于定位物料 `ProductId` |
| 库存数量 | 是 | 100.00000000 | 用于更新 `Qty` |
| 单位 | 是 | KG | 用于定位 `UOMId` |
| SAP批号 | 是 | SAPBATCH001 | 用于匹配并写入 `ProductionLotNO` |
| 批号 / LotSN | 否 | LOT20260618001 | 盘点来源通常不提供，不作为必填字段和主匹配键 |

### 2.2 数据质量要求
- 工厂、仓库、物料号、单位、SAP批号不能为空。
- 库存数量必须为数字，且不能小于 `0`。
- 同一个工厂、仓库、物料号、SAP批号在同一批盘点数据中不允许重复。
- 文本字段导入前后应去除首尾空格，避免因空格导致匹配失败。

## 3. 用户故事

### US-001：按 Excel 盘点结果更新库存数量
**作为** 仓库管理员，  
**我希望** 将盘点 Excel 中的库存数量更新到 MES 库存表，  
**以便** MES 库存和现场实际库存一致。

**验收标准：**
- [ ] Excel 中存在且 MES 中已存在的 `工厂 + 仓库 + 物料 + SAP批号`，按 `FactoryId + WorkcenterId + ProductId + ProductionLotNO` 匹配 `WW_RMInventory`。
- [ ] 一行盘点结果匹配到多行库存时，按 `CreateDate DESC, WWId DESC` 从新到旧累计保留库存，直到累计数量等于盘点数量。
- [ ] 完整保留的库存批次保持原 `Qty` 不变；最后一个保留批次如超过盘点数量，只将 `Qty` 调整为剩余需要数量，批次号和其他批次信息不变。
- [ ] 被保留记录的 `IsStorage` 设置为 `1`，单位按盘点数据同步更新。
- [ ] 更新完成后返回本次更新行数。

---

### US-002：盘点结果中新增的 SAP 批次写入库存表
**作为** 仓库管理员，  
**我希望** Excel 中有但 MES 库存表中没有的 SAP 批次能自动新增，  
**以便** 补齐现场实际存在但系统缺失的库存。

**验收标准：**
- [ ] Excel 中存在、MES 中不存在的 `工厂 + 仓库 + 物料 + SAP批号`，新增到 `WW_RMInventory`。
- [ ] 新增记录的 `Qty` 使用 Excel 库存数量。
- [ ] 新增记录的 `FactoryId`、`WorkcenterId`、`ProductId`、`UOMId` 能正确解析并写入。
- [ ] 新增记录的 `ProductionLotNO` 使用 Excel `SAP批号`。
- [ ] 新增记录不依赖盘点来源 `LotSN`；`LotSN` 留空或使用系统内部生成值需开发前确认。
- [ ] 新增记录的 `IsStorage` 默认为 `1`。
- [ ] 新增完成后返回本次新增行数。

---

### US-003：Excel 中缺失的 SAP 批次置为不在库
**作为** 仓库管理员，  
**我希望** MES 中存在但 Excel 盘点结果中没有的 SAP 批次被标记为不在库，  
**以便** 清理系统中已经不存在的库存。

**验收标准：**
- [ ] 只处理本次盘点涉及的仓库范围。
- [ ] 同一个仓库内，MES 中 `IsStorage=1` 但 Excel 中不存在的 `工厂 + 仓库 + 物料 + SAP批号`，将 `IsStorage` 更新为 `0`。
- [ ] 同一 SAP 批次下超过盘点数量之外的更旧库存批次，也将 `IsStorage` 更新为 `0`。
- [ ] 不物理删除 `WW_RMInventory` 记录。
- [ ] 置出库完成后返回本次置出库行数。

---

### US-004：按仓库独立处理，失败不影响其他仓库
**作为** 系统维护人员，  
**我希望** 每个仓库独立事务处理，  
**以便** 某个仓库数据异常时，其他仓库仍然可以正常完成盘点更新。

**验收标准：**
- [ ] 每个仓库单独开启事务。
- [ ] 某仓库处理失败时，仅回滚该仓库数据。
- [ ] 其他仓库继续处理，不被失败仓库中断。
- [ ] 返回结果中能看到每个仓库成功或失败原因。

---

### US-005：预览模式校验盘点数据
**作为** 系统维护人员，  
**我希望** 在正式更新前先预览校验结果，  
**以便** 提前发现工厂、仓库、物料、单位或数量异常。

**验收标准：**
- [ ] 支持 `DryRun=1` 预览模式。
- [ ] 预览模式只校验和统计，不修改 `WW_RMInventory`。
- [ ] 预览结果展示预计更新、新增、置出库数量。
- [ ] 预览失败时返回清晰错误原因。

## 5. 业务规则

### 5.1 匹配规则
库存记录按以下组合匹配，不再使用盘点来源 `LotSN` 作为主匹配键：

```sql
FactoryId + WorkcenterId + ProductId + ProductionLotNO
```

盘点数据中的 `SAP批号` 对应 `WW_RMInventory.ProductionLotNO`。同一个匹配组合可能命中多行库存，因为 MES 内部可能存在多个 `LotSN` 批次；处理时必须按创建时间从新到旧累计保留。

### 5.2 更新规则
- 匹配到已有库存记录时，不是只保留一条，而是按 `CreateDate DESC, WWId DESC` 从新到旧累计保留多个批次，直到累计数量等于盘点数量。
- `RunningQty <= StockQty` 的库存批次完整保留，原 `Qty` 不变，仅同步 `IsStorage=1`、`ModifyDate=GETDATE()`。
- `RunningQty - Qty < StockQty AND RunningQty > StockQty` 的库存批次作为最后保留批次，`Qty` 调整为 `StockQty - (RunningQty - Qty)`，批次号和其他批次信息不变。
- `RunningQty - Qty >= StockQty` 的更旧库存批次超出盘点数量，将 `IsStorage` 设置为 `0`。
- `ProductionLotNO` 保持为盘点 SAP 批次；本期不同步写入 `SAPRemark`。

### 5.3 新增规则
- 未匹配到库存记录时，新增 `WW_RMInventory`。
- `WWId` 使用系统现有主键生成方式生成。
- `Qty` 和 `OrgQty` 使用盘点库存数量。
- `FactoryId`、`WorkcenterId`、`ProductId`、`UOMId` 来自主数据解析结果。
- `ProductionLotNO` 使用 Excel SAP 批号。
- `LotSN` 不再使用盘点来源字段；新增库存时使用系统批号规则 `WW_MP_LotSN` 生成 MES 内部批号。
- `IsStorage=1`。

### 5.4 置出库规则
- 仅处理本次盘点涉及到的仓库。
- 处理本次盘点仓库内全部在库库存；如果库存表中该仓库存在某物料，但 Excel 中该仓库不存在该物料，则将该物料库存 `IsStorage` 更新为 `0`。
- 对 `WW_RMInventory` 中 `IsStorage=1`，但本次盘点数据中不存在的 `FactoryId + WorkcenterId + ProductId + ProductionLotNO`，将 `IsStorage` 更新为 `0`。
- 对同一 SAP 批次匹配到的多行库存，超出盘点数量之外的更旧批次也需要将 `IsStorage` 更新为 `0`。
- 置出库时同步更新 `ModifyDate=GETDATE()`。

## 6. 异常与提示

| 场景 | 处理方式 | 提示建议 |
|---|---|---|
| 盘点数据为空 | 阻断处理 | 盘点数据不能为空 |
| 工厂不存在 | 阻断对应仓库处理 | 工厂在 MES 中不存在 |
| 仓库不存在 | 阻断对应仓库处理 | 仓库在 MES 中不存在或名称不匹配 |
| 物料不存在 | 跳过该行或阻断该仓库，需实施时确认 | 物料号在 MES 中不存在 |
| 单位不存在 | 跳过该行或阻断该仓库，需实施时确认 | 单位在 MES 中不存在 |
| 数量为空或小于 0 | 跳过该行或阻断该仓库 | 库存数量不合法 |
| 同批数据重复 | 阻断处理 | 同一工厂、仓库、物料、SAP批号存在重复数据 |

## 7. 非功能需求

| 类型 | 要求 |
|---|---|
| 数据库 | 使用 SQL Server 编写 SQL 和存储过程 |
| 事务 | 以仓库为单位独立事务，失败仓库单独回滚 |
| 性能 | 盘点数据量较大时应优先使用集合更新，避免大量逐行游标 |
| 安全 | 不使用 SQL 字符串拼接，避免注入风险 |
| 可维护性 | 每段核心 SQL 逻辑必须有中文注释 |
| 可追踪性 | 返回处理批次号、仓库级结果、更新/新增/置出库数量 |
