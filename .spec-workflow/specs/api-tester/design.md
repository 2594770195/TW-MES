## 1. 技术方案

### 1.1 技术选型
- **框架**：原生 HTML5 + CSS3 + Vanilla JavaScript（ES2020）
- **理由**：纯静态网页无需构建工具，零依赖，可直接双击 `index.html` 在浏览器运行
- **JSON 高亮**：自行实现轻量 JSON 语法高亮渲染函数，无需引入第三方库
- **样式**：手写 CSS 变量 + Flexbox 布局，现代深色/浅色主题

### 1.2 文件结构
```
d:\apitest2\
├── index.html          # 主页面（单文件，HTML + 内联 CSS + 内联 JS）
└── .spec-workflow/     # 规格文档（不参与页面功能）
```
> 采用单文件方案（HTML 内联 CSS/JS），最大化便携性，无需任何依赖。

## 3. 核心模块设计

### 3.1 请求构建模块（`buildRequest`）
- **输入**：method、url、headers 数组、body 字符串、bodyType
- **处理**：
  1. 非空校验：url 为空则抛出提示错误
  2. URL 格式校验：使用 `new URL(url)` 捕获异常
  3. 组装 `fetch` 的 `RequestInit` 对象
  4. GET 方法时忽略 Body
  5. Body 为 JSON 类型时，若 `Content-Type` Header 未设置则自动追加
- **输出**：`{ url, init }` 供 fetch 调用

### 3.2 请求发送模块（`sendRequest`）
- **输入**：`{ url, init }`
- **处理**：
  1. 记录开始时间戳
  2. 调用 `fetch(url, init)`，设置超时（AbortController，30s）
  3. 捕获网络错误、超时错误，转换为友好提示
  4. 计算耗时 = 结束时间戳 - 开始时间戳
- **输出**：`{ status, statusText, body, elapsed }`

### 3.3 响应渲染模块（`renderResponse`）
- **输入**：`{ status, statusText, body, elapsed }`
- **处理**：
  1. 渲染状态码（含颜色 class 判断：2xx/4xx/5xx）
  2. 渲染耗时
  3. 尝试 `JSON.parse(body)`，成功则调用 `highlightJson` 高亮渲染
  4. 失败则以 `<pre>` 原始文本展示
- **输出**：DOM 更新

### 3.4 JSON 高亮模块（`highlightJson`）
- **输入**：已解析的 JSON 对象
- **处理**：递归遍历对象，用 `<span class="json-xxx">` 包裹各类型值
- **输出**：HTML 字符串

### 3.5 Header 编辑器模块
- 动态渲染 Key-Value 输入行列表
- 支持"添加行"与"删除行"操作
- 读取时过滤空 Key 的行

## 4. 数据流

```
用户点击"发送"
  → 表单校验（URL 非空 + 格式合法）
  → buildRequest（组装 headers / body / method）
  → sendRequest（fetch + 超时控制 + 计时）
  → renderResponse（状态码着色 + JSON 高亮 / 原始文本）
  → DOM 更新展示结果
```

---

## 5. 关键约束与边界处理

| 场景 | 处理方式 |
|---|---|
| URL 为空 | 阻断请求，输入框边框变红，显示提示文字 |
| URL 格式非法 | 阻断请求，显示"URL 格式不正确"提示 |
| GET 方法有 Body | 忽略 Body，不传入 fetch |
| Body 非合法 JSON | 以 raw text 方式发送，不做拦截 |
| 响应非 JSON | 以 `<pre>` 原始文本展示，不报错 |
| 请求超时（>30s） | 中止请求，显示"请求超时，请检查网络或服务地址" |
| 网络断开/CORS 错误 | 捕获 fetch 异常，显示"网络错误，请检查 CORS 配置或网络连接" |
| Header Key 为空 | 过滤该行，不发送空 Key 的 Header |
| 响应内容超长 | 响应区域限高并启用纵向滚动条 |
