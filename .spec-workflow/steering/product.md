# Product Steering

## Product Vision
提供一款面向开发与测试人员的 API 测试平台，支持接口请求发送、响应校验、自动化测试用例管理与结果追踪。

## Target Users
| 用户角色 | 核心目标 | 关键痛点 |
|---|---|---|
| 后端开发工程师 | 快速验证接口功能是否正确 | 调试工具繁琐，缺乏用例复用能力 |
| 测试工程师 | 管理和执行接口自动化测试 | 测试数据维护成本高，报告不直观 |
| 项目负责人 | 了解接口测试覆盖率与质量状态 | 缺乏统一的测试结果可视化入口 |

## Key Features

### MVP (Must Have)
- 接口请求发送（支持 GET / POST / PUT / DELETE）
- 请求参数、Header、Body 配置与保存
- 响应结果展示与断言校验
- 测试用例管理（创建、编辑、分组）
- 测试执行与结果记录

### Next (Should/Could Have)
- 测试报告导出（PDF / HTML）
- 环境变量与全局变量管理
- CI/CD 集成支持
- Mock 服务功能

## Business Objectives
| 目标 | KPI | 目标值 | 周期 |
|---|---|---|---|
| 提升接口测试效率 | 人均用例执行耗时 | 降低 40% | 上线后 3 个月 |
| 用例复用率 | 复用率占比 | ≥ 60% | 上线后 6 个月 |
| 系统稳定性 | 核心功能可用率 | ≥ 99.5% | 持续 |

## Product Principles
- 操作简洁直观，减少学习成本
- 数据与配置可导入导出，避免厂商绑定
- 优先保障核心测试流程的稳定性

## Scope Boundaries
- 本阶段不包含性能压测功能
- 本阶段不包含 UI 自动化测试
- 本阶段不包含多租户 / SaaS 化部署

## Milestones
- M1（第 1-4 周）：完成接口请求与响应核心功能，MVP 可用
- M2（第 5-8 周）：完成用例管理与测试执行流程
- M3（第 9-12 周）：完成测试报告与环境变量管理
