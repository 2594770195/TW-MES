# 两套库存合并——调拨叠加货位码移动 方案设计

> 作者：<Irving></irving>  日期：2026-09-30
> 状态：待确认（含 3 个待决策问题）

## 1. 背景与目标

MES 现有两套库存管理，需合并：

| 套系      | 核心表/过程                                                                                                                    | 粒度                            | 位置表达                                         |
| --------- | ------------------------------------------------------------------------------------------------------------------------------ | ------------------------------- | ------------------------------------------------ |
| 原生库存  | `WW_RMInventory`                                                                                                             | 1 个 MES 批次(LotSN) = 1 条记录 | FactoryId / WorkcenterId / CellId                |
| 容器/货位 | `ZR_ContainerCode`、`ZR_ToFac_ContainerCode`、`ZR_ContainerCodeDetails`、`ToFac`；过程 `PDA_ToFac`、`PDA_ToFac_PO` | 1 个 MES 批次 = N 个容器        | `ZR_ContainerCodeDetails.CodeStatus`（货位码） |

目标：**调拨时在原生调拨基础上，同步增加「货位码(CodeStatus)」的移动记录**。

## 2. 已确认的业务规则

1. **货位码 = `CodeStatus`**（存储于 `ZR_ContainerCodeDetails.CodeStatus`，非容器码本身）。
2. 移动时是**部分容器动**（一个批次可只动其中若干容器）。
3. **目标货位单独扫码**。
4. 调拨后**新增一条 `ZR_ContainerCodeDetails` 货位移动记录**，其余信息（容器码、绑定批次等）不变。
5. 调拨数量仍按 **MES 批次数量**；容器中的重量 `num` 独立，不参与调拨数量计算。
6. 外购 PO 分支（`PDA_ToFac_PO`）一并合并，规则与自制一致。
7. 两套的纽带字段：`WW_RMInventory.LotSN = ZR_ToFac_ContainerCode.BoxLotSn`。

## 3. 改动点清单

### 3.1 过程层面（新增/修改）

- **新增** PDA 货位移动过程（如 `PDA_ContainerLocMove`），参考 `PDA_ToFac` 的接口骨架：
  - 入参：`@LotSN`(MES批次)、`@ContainerCode`(容器码)、`@CodeStatus`(目标货位码)、`@num`(实际数量，默认带出容器重量)、`@Remark`。
  - 逻辑：校验批次/容器存在 → 校验容器当前绑定批次与 `@LotSN` 一致 → 若需拆批则联动拆批（见问题 1）→ 插入一条 `ZR_ContainerCodeDetails`（`CodeStatus`=目标货位，`num`=实际数量）→ 返回。
- **扩展/联动** `Txn_MaterialLotSplit`（拆分）与 `PDA_ToFac`/`PDA_ToFac_PO`：拆批后需同步容器绑定关系（见 4.1）。
- **挂接原生调拨**：在原生调拨确认/审核环节（`ProductAllotApproveDoMethod` 或 WMS 回写 `WebAPI_ProductAllotFromWMS` 后）触发货位移动，或由操作员在 PDA 端独立执行货位移动。

### 3.2 表层面

- 原则上**无需新增字段**：货位码已落在 `CodeStatus`，移动即新增明细。“某容器当前货位”可由 `ZR_ContainerCodeDetails` 按 `createdate desc` 取最新 `CodeStatus` 得到。
- 若后续需要频繁按“当前货位”查询，可评估在 `ZR_ContainerCode` 增加冗余字段 `CurrentCodeStatus`（当前货位码），以 `ZR_ContainerCodeDetails` 为真值，二者对账。**待定，非必需**。

### 3.3 客户端/扫描交互层面

- 新增/调整一个 PDA 界面，流程见问题 2。

## 4. 可能的问题与边界

1. **拆批后容器归属丢失**：现有 `Txn_MaterialLotSplit` 只减原批次数量、生成新批次，**不处理 `ZR_ContainerCode`/`ZR_ToFac_ContainerCode` 绑定**，拆批后无法定位“新批对应哪个容器”。必须补绑定联动。
2. **数量口径冲突**：规则 5（调拨按批次数量）与拆批场景（按容器/桶数）存在张力，需明确拆批时新批次的 `Qty` 取值（见问题 1）。
3. **部分容器移动后的批次剩余量**：`WW_RMInventory.Qty` 是否同步扣减？若不扣，库存账与货位/容器账不一致，需对账。
4. **重复/并发移动**：同一容器被并发调拨需防重复扣减（是否加锁需评估后与用户确认）。
5. **货位码合法性**：目标 `CodeStatus` 是否需校验属于目标库位/车间（类似原生 `Cell`），避免扫到无效货位。
6. **外购 PO 差异**：`PDA_ToFac_PO` 用 `BoxLotSn`（箱号）+ `VendorDeliveryItemLot`/`WW_RMInventory` 双归属，合并时需统一“货位移动”的写入口径。

## 5. 三个待决策问题的分析与建议

### 问题 1：批次数量 ≠ 实际调拨数量（拆批）

场景：1 个 MES 批次实际 3 桶，只调 1 桶。

**建议方案：自动拆批（复用 `Txn_MaterialLotSplit`，并补容器绑定联动）。**

- 拆批方向：**调走部分生成新批号（新条码），留在原货位的仍是旧批号**。
  - 优点：原仓库其余 2 桶条码不变，只需给调走的 1 桶打新条码；新条码天然对应新货位。
  - 代价：目标仓库需打新条码（规则“仓库要打新条码”已确认）。
- 拆批后“批 ↔ 容器码”对应：拆批时必须让操作员**指定/扫描要调走的那 1 桶的 `ContainerCode`**，拆批动作将其绑定到新批号：
  - `ZR_ToFac_ContainerCode` 新增/更新该容器的 `BoxLotSn = 新批号`；
  - `ZR_ContainerCode.CurrentProudctionLotSN` 同步为新批号；
  - `ZR_ContainerCodeDetails` 记录“拆批 + 移动”流水。
- 新批次 `Qty` 取值：**待确认** —— 是取该容器重量 `num`，还是取调拨单 `AllotQty`？两者在“按桶调拨”场景应相等，但需明确以谁为准。
- 需确认：是否允许“一次调拨拆出多桶、分别绑多个容器”。

### 问题 2：目标货位码怎么扫

两个候选流程：

- 方案 A（先送后扫）：东西送到后，依次扫 批次、货位码、容器码、实际数量。
- 方案 B（先扫容器码）：先扫 容器码、实际数量；目标货位码放货时再扫。

**建议采用方案 B，并拆成两步（更贴合搬运动作，且源位可即时校验）：**

1. 【取货】扫批次 `LotSN`（或由调拨单带出）→ 扫容器码 `ContainerCode` → 系统带出该容器重量 `num`（可改为实际扫码数量）。
2. 【放货】扫目标货位码 `CodeStatus` → 确认 → 写 `ZR_ContainerCodeDetails` 移动记录。

- 优点：取货时就能校验“容器是否属于该批次”“数量是否正确”，放货动作延迟到货位确定后，支持“一个批次分多次、多个目标货位”。
- 需确认：是否上线时还需扫一次“源货位码”做离开校验（可选项，用于防错）。

### 问题 3：水性/活性灌墨是否要做调拨

现状：`PDA_FPInkCheckInput_PL`（成品灌墨）是**生产工序/报工**（灌墨规程 `UVGM/FSGM/HXGM/SXGM`）；`Txn_MOAllotRequestDoMethod` 里已有 水性(SX)/活性(HX) 的“工单调拨 → 生成调拨单”。

**建议区分两类动作：**

- **库存调拨（原料/半成品从中间仓拨到车间/线边仓）**：是“调拨”，需保留，并且这一步才需要**叠加货位码移动**。
- **灌墨本身（生产工序流转/报工）**：不是库存调拨，**不改 `WW_RMInventory` 账、不通知 WMS/SAP，只管货位码（记录/更新其所在 `CodeStatus`）**。

**需确认**：灌墨工序中，货位码是否需要随生产流转自动更新（例如从“暂存货位”移到“灌墨工位”对应的货位码）？还是仅在上/下线时人工扫一次货位码？
