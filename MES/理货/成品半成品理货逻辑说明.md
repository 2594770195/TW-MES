# 成品工单半成品理货逻辑说明

> 版本：v1.2（2026-11-12）
> 涉及过程：
> - `MOSemiFinishedLotAllocationBatchByProductionLotNoDoMethod`（理货分配 / 确认 / 取消分配）
> - `PDA_FPInkCheckInput_PL`（成品灌墨扣数 / 已扣数）
> 变更：v1.1 修复"取消分配状态写错"与"未扣完理货被整行释放为已扣数"；v1.2 明确 SAP 同步为**同步调用、失败回滚**。

---

## 一、业务定位

- 成品工单（MO）灌墨前，仓库先为工单的半成品物料行做「理货」：把在库半成品批次
  （按 SAP/生产批次 `ProductionLotNO`，或 MES 批次 `LotSN`）预分配给该工单。
- 理货记录表 `MOSemiFinishedLotAllocation` **只记录预分配关系，不直接扣减库存**。
- 灌墨（`PDA_FPInkCheckInput_PL`）时才**实时扣减 `WW_RMInventory` 库存**；
  扣减完成后，将"已按理货数量全部扣完"的理货记录释放为**已扣数**。

---

## 二、核心表字段（`MOSemiFinishedLotAllocation`）

| 字段 | 类型 | 含义 |
|---|---|---|
| MOSemiFinishedLotAllocationId | char(12) | 主键 |
| MOId / MOName / MOItemId | - | 成品工单 / 工单号快照 / 工单半成品物料行 |
| ProductId | char(12) | 半成品物料 |
| WWId / LotSN / ProductionLotNO | - | 库存ID / MES批次 / SAP生产批次（按 ProductionLotNO 分配时 LotSN、WWId 留空） |
| Qty | decimal(18,8) | 理货分配数量 |
| **ConfirmStatus** | char(1) | 确认状态：0=未确认（仅本次分配中占用），1=已确认（全局占用） |
| **IsOccupyAllocatedQty** | bit | 是否占用：1=占用（未确认或已理货），0=不占用（已扣数） |
| **DeleteFlag** | char(1) | 逻辑删除：0=有效，1=取消分配 |
| allow_batch | bit | 是否分批：0=不分批（确认时需足量），1=分批（可部分分配） |

---

## 三、状态机（三字段组合）

| 状态 | ConfirmStatus | IsOccupyAllocatedQty | DeleteFlag | 是否占用库存 | SAP 状态 |
|---|---|---|---|---|---|
| 未确认（预分配） | 0 | 1 | 0 | 仅本次分配占用 | 不同步 |
| **已理货** | 1 | 1 | 0 | 全局占用 | 已理货 |
| **已扣数** | 1 | 0 | 0 | 不占用 | 已扣数 |
| **取消分配** | 1 | 1 | 1 | 不参与汇总（已删除） | 取消 |

规则：

1. `ConfirmStatus='0'` 的占用仅在本次分配计算中生效；`ConfirmStatus='1'` 才代表全局占用库存。
2. **SAP 相关逻辑的默认前提条件是 `ConfirmStatus='1'`**，未确认行不触发任何 SAP 同步。
3. 已扣数行不允许取消分配（需要回冲 SAP，当前不支持）。
4. 取消分配只置 `DeleteFlag='1'`，**保留 `IsOccupyAllocatedQty=1`**，以区别于"已扣数"。

## 四、理货分配流程（`MOSemiFinishedLotAllocationBatchByProductionLotNoDoMethod`）

### 4.1 AutoAssign（自动分配）

- 按工单输入顺序逐单循环；单内按物料行行序，生产批次按生产日期先进先出（FIFO）。
- 写入记录：`IsOccupyAllocatedQty=1`、`ConfirmStatus='0'`、`DeleteFlag='0'`。
- 可用数量 = `SUM(WW_RMInventory.Qty) − SUM(已占用理货数量)`；
  占用口径：

  ```
  DeleteFlag='0' AND IsOccupyAllocatedQty=1
  AND ( ConfirmStatus='1'
        OR (ConfirmStatus='0' AND MOId IN (本次工单清单)) )
  ```

### 4.2 ConfirmLot（理货确认 → 已理货）

- 前置校验：生产批次库存充足、不分批物料行分配足量。
- 批量 `UPDATE ... SET ConfirmStatus='1'`（0→1），转为全局占用 = 已理货。
- **本次新增**：UPDATE 使用 `OUTPUT ... INTO #ConfirmedRows` 捕获本次实际变化行，供 SAP 同步使用。

### 4.3 DeleteLot（取消分配）

- 三态区分处理：
  - 未确认记录（`ConfirmStatus='0'`）：置 `DeleteFlag='1'` 且 `IsOccupyAllocatedQty=0`，不触发 SAP；
  - 已理货记录（`ConfirmStatus='1'` 且 `IsOccupyAllocatedQty=1`）：仅置 `DeleteFlag='1'`，保留占用标记，最终形态
    `ConfirmStatus='1'`、`IsOccupyAllocatedQty=1`、`DeleteFlag='1'`，需同步 SAP 取消；
  - 已扣数记录（`ConfirmStatus='1'` 且 `IsOccupyAllocatedQty=0`）：**禁止取消**，直接报错。

### 4.4 GetInventory / GetAllocatedLots

- 均过滤 `DeleteFlag='0' AND IsOccupyAllocatedQty=1`，因此**已扣数行和取消分配行不显示、不参与分配**。

## 五、已扣数逻辑（`PDA_FPInkCheckInput_PL`）

### 5.1 灌墨扫描准入

- 扫描批次必须命中有效理货记录：
  `DeleteFlag='0' AND IsOccupyAllocatedQty=1 AND ConfirmStatus='1'`。
- 理货数量 `@TallyQty` = 该工单物料行该生产批次的理货数量合计。
- 已扣数数量 `@TallyUsedQty` = `LoadingItemLotRecord` 中**同一工单物料行 + 同一 SAP 批次累计已扣数量**
  （v1.1 修正：不再只统计当前上料会话，避免切换上料会话后重复扣满理货数量）。
- 剩余理货数量 `@TallyRemainQty = @TallyQty − @TallyUsedQty`。
- 本次扣减数量 `@UsedQty = MIN(MES批次可用库存, @TallyRemainQty)`，并校验不超过工单剩余需求。
- 灌墨上料在同事务内实时扣减 `WW_RMInventory`，写 `LoadingItemLotDetail` / `LoadingItemLotRecord`。

### 5.2 释放占用 → 已扣数（v1.1 修正）

- 过站报工 / 批次下线完成后，**仅将"实际扣减数量 ≥ 理货数量"的记录释放为已扣数**：

  ```sql
  UPDATE A
  SET A.IsOccupyAllocatedQty = 0
  FROM MOSemiFinishedLotAllocation A
  INNER JOIN (
      -- 按 工单物料行 + 生产批次 汇总该工单全部上料会话的实际扣减数量
      SELECT LID.MOItemId, WRI.ProductionLotNO, SUM(LIR.Qty) AS UsedQty
      FROM LoadingItemLotRecord LIR
      INNER JOIN LoadingItemLotDetail LID ON LID.LoadingItemLotDetailId = LIR.LoadingItemLotDetailId
      INNER JOIN WW_RMInventory WRI ON WRI.LotSN = LIR.LotSN
      WHERE LID.MOItemId IN (SELECT mi.MOItemId FROM MOItem mi WHERE mi.MOId = @MOId)
      GROUP BY LID.MOItemId, WRI.ProductionLotNO
  ) U ON U.MOItemId = A.MOItemId AND U.ProductionLotNO = A.ProductionLotNO
  WHERE A.MOId = @MOId
      AND A.DeleteFlag = '0' AND A.IsOccupyAllocatedQty = 1 AND A.ConfirmStatus = '1'
      AND U.UsedQty >= A.Qty;
  ```

- 修正前的问题：
  - 前两处按 `MOItemId` 整行释放、第三处（`CMDLOTMOVE` 批次下线）按 `MOId` 整单释放；
  - 理货 100、实际只扣 60 时，剩余 40 也被置为已扣数，会造成 **SAP 多扣 40**。
- 修正后：未扣完的理货记录继续保持 `IsOccupyAllocatedQty=1`（仍为已理货），
  可继续灌墨扣数，或由仓库执行取消分配。
- 三处释放均使用 `OUTPUT ... INTO @DeductedRows` 捕获本次变化行，供 SAP 同步。

## 六、SAP 同步触发点

| 触发点 | 所在过程 | 状态变化 | SAP 动作 | 当前状态 |
|---|---|---|---|---|
| 理货确认 | ConfirmLot | ConfirmStatus 0→1 | 已理货 | 已捕获变化行，接口 TODO |
| 过站报工释放 | PDA_FPInkCheckInput_PL | IsOccupyAllocatedQty 1→0 | 已扣数 | 已捕获变化行，接口 TODO |
| 批次下线释放 | PDA_FPInkCheckInput_PL | IsOccupyAllocatedQty 1→0 | 已扣数 | 已捕获变化行，接口 TODO |
| 取消分配 | DeleteLot | DeleteFlag 0→1 | 取消 | 已定位触发条件，接口 TODO |

同步前提：**仅 `ConfirmStatus='1'` 的行发生变化才同步**。

同步方式（已确认）：**同步调用，不成功即回滚**。

1. SAP 接口在本地事务 `COMMIT` 之前调用，属于同步调用，不是异步、不走 outbox；
2. 接口返回非 0 时立即 `ROLLBACK` 本地事务并返回 `-1`，本地状态不发生变更，保证 MES 与 SAP 一致；
3. 未发生状态变化（变化明细为空）时不调用接口，避免无效同步；
4. 接口过程待实现，过程名暂定 `APISyncU_SemiFinishedTallyToSAP`，返回约定 0=成功、非 0=失败。

| 触发点 | 事务 | SAP 失败处理 |
|---|---|---|
| ConfirmLot 已理货 | `ConfirmLot` | `ROLLBACK TRANSACTION ConfirmLot` + RETURN -1 |
| DeleteLot 取消分配 | `DeleteLot` | `ROLLBACK TRANSACTION DeleteLot` + RETURN -1 |
| 过站报工 / 批次下线已扣数 | 新增 `TallySap` | `ROLLBACK TRANSACTION TallySap` + RETURN -1 |

## 七、遗留待确认事项

1. **部分扣数后的取消分配**：一条理货记录允许被多次分批扣数（灌墨多次），已扣数部分与未扣部分的归属需明确；
   当前实现是"扣满才置已扣数"，未扣满的记录仍是整条已理货，取消即整条取消。
2. **工厂完工时未用完的理货**：工单完工/任务完工时若仍有未扣完的理货数量，需明确由谁、在什么时点取消，
   否则会长期占用库存。
3. **手工输入数量分支**（`PDA_FPInkCheckInput_PL` 中按 `@InputNumber` 确认数量的旧分支）尚未校验"剩余理货数量"，
   若该入口仍在使用，需补充同样的理货上限校验。
4. **zpp12 报表口径**：当前 Qty 语义未变（仍为理货分配数量），报表"已理货"= `IsOccupyAllocatedQty=1 AND ConfirmStatus='1'`，
   在部分扣数场景下会显示原始理货数量而非剩余数量，需业务确认展示口径。
